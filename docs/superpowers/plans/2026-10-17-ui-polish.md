# UI Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the full application easier to scan, more engaging, and reliably usable on 390px/430px mobile viewports while preserving the notebook identity and existing learning behavior.

**Architecture:** Keep the current React route/page structure and CSS-first token system. Improve shared shell and surfaces first, then apply page-specific hierarchy in Home, Bab Detail, Susun, and Partikel. Keep state/data logic unchanged unless a presentational component needs an existing value.

**Tech Stack:** React 19, TypeScript, Vite 6, Tailwind CSS v4, React Router v7, Zustand, CSS modules imported through `paper.css`, Vitest.

## Global Constraints

- No new UI dependencies.
- Tailwind v4 CSS-first — do not add `tailwind.config.js` or `postcss.config.js`.
- Do not hardcode hex/rgba colors in `paper.css`; use theme tokens.
- Do not add `transition:` to `paper.css`; animation rules belong in `motion.css`.
- Preserve full-bleed containers; do not reintroduce `max-w-*` on page wrappers.
- Preserve lazy loading, dynamic bab loading, `meta`, and code splitting.
- Do not change verified learning facts or bab data.
- Zustand setters must remain idempotent; selectors must not return fresh fallback literals.
- Mobile is the baseline: validate at 390px and 430px with CDP device emulation.
- Every final claim requires evidence from `npm run typecheck`, `npm run validate`, `npm run build`, `npm run test`, and `npm run check:full`.
- Do not commit `public/audio`, secrets, or unrelated worktree changes.
